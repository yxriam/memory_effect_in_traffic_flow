# T03 预测实验设计：检验三条假设（草案）

- 执行：Claude Code 和用户讨论定稿　审查：Codex
- 状态：草案（2026-10-23）。定稿前不开始跑大实验；定稿后拆成若干个执行任务（T03a、T03b…），每个按模板写判据。
- 关联：`STATUS.md` 第 6 节；中期报告第一部分 3(7) 和第五部分第 3 项

## 为什么做

学位论文第二部分要回答：第一部分得到的原理（历史的作用集中在少数几个变量上，显式输入这些变量比加长历史更省数据）能不能在现在常用的预测模型上带来实际收益。这是“对预测有什么用”的直接证据。目的不是追求最好的精度，而是在同一个常用模型上比较不同的输入，所以不追最新的复杂模型。

## 共同规则

- 比较的各个设置用同一批测试样本；每个设置至少 3 个种子，报均值和范围。
- 比较不同历史长度时，固定模型容量（参数量）和训练数据量。
- 特征只用当前及以前的数据计算，计算窗口计入历史长度（例如用最近 1 s 的位置算加速度，历史长度就算 1 s）。
- 去抖动只用于输入和训练数据，测试目标保持原始序列。
- 对照：马尔科夫链（n-gram，回退平滑并逐层调 β）；轨迹预测另加匀速、匀加速模型。
- 结论只说“该模型在该数据量下能用上多长的历史”。
- 训练按轮次存检查点、可续跑（`prediction/resume.py`）。本机 GPU 是 GeForce MX250，大实验先用小规模估计时间。

## 假设一：显式输入关键变量能否代替更长的历史

### 1a 车辆轨迹（highD）

- 数据：`highd_full`（原始发布版，含速度、加速度、前车编号），按车辆划分训练、验证、测试；按 0.2 s 取样，与已有的 highD 分析一致。
- 任务：预测未来 1–5 s 的位置，纵向、横向分开统计，换道样本单独统计。
- 输入组合：
  1. 只有自车位置序列，历史 W = 0.4、1、2、3 s；
  2. 当前运动状态（纵向、横向速度和加速度，用最近的位置向后差分得到）加短窗口；
  3. 再加前车状态（间距、相对速度、前车加速度）。
- 模型：一个常用的序列模型（如 LSTM 编码器），各组合参数量相同；基线为匀速、匀加速。
- 指标：ADE，1、3、5 s 的 FDE；另报模型大小和推理时间。
- 判据（待定稿）：组合 2 或 3 在短窗口下的误差与最长窗口相差不超过种子间的波动 → 假设一在 highD 上成立；长窗口仍明显更好 → 报告差多少、差在哪类样本（如换道）。
- 注意：highD 的位置经过平滑（用到了前后的观测），所有输入都带一点未来信息。各组合受到的影响相同，比较仍然公平，但绝对误差偏乐观，论文里要写明。数据集自带的速度、加速度也可能用了对称窗口，主分析用向后差分，自带值只作对照。

### 1b 下一位置（出租车、GeoLife）

- 数据：现有的 `taxi_traj20` 是每条轨迹自己的 20×20 网格，不同轨迹的格子含义不同，不能加全局特征。需要新导出：出租车用 0.002° 全局网格，切分和划分与 `controls/heading_state.py` 相同，每步附带设备方向、格内位置、速度档；GeoLife 用 0.001° 全局网格（`export_data.py geolife` 已有），每步附带方向。注意 `heading_state.runs` 的航向用的是进入当前格子之前 10–30 m 的定位点，那个点在当前格子之外（多在上一个格子里）；按“计算窗口计入历史长度”的规则，要么改用当前格子内、离开之前的定位点算方向，要么把这个输入算作看了上一格的一小段，在结果里写明。交通方式只有标注过的那部分轨迹有。
- 输入：最近 k 个格子，k = 1、2、4、8、32，加或不加当前的方向等标签。
- 模型：`prediction/neural_hist.py` 的 LSTM、Transformer，把标签嵌入后与格子嵌入拼接，参数量固定。
- 指标：交叉熵（bits/步）、top-1、top-5。
- 判据（待定稿）：k = 1–2 加标签能否达到 k = 8–32 不加标签的水平。
- 与 T01 的关系：网络的容量固定，一个没有信息的标签不会降低它的留出交叉熵，所以这里没有计数模型里“状态切细”的问题。出租车上“k = 1 加设备方向”对“k = 2”的比较，可以直接回答 T01 用计数模型可能回答不清的问题。

### 1c 航空（显式给出行程起点）

- 输入：“当前机场＋起点”对最近 k 站（k = 2、4、8）。
- 指标同 1b。分开报告：全部步；前面至少 4 站的步；4 站窗口不含起点的步（约占至少 4 站的步的 9%，样本少，只作参考）。

## 假设二：历史的收益怎样随训练数据量变化

- 目的：语言模型里“数据越多，越长的上下文越有用”已有定论，这里不去证明它，而是量化这几类轨迹数据上的关系，判断第一部分“依赖集中在最近几步”有多少是数据量造成的。
- 做法：训练数据取全部的 1/16、1/8、1/4、1/2、1（按车辆、用户或行程抽样），测试集和模型容量不变；每个数据量下比较 k = 1、2、4、8 的交叉熵，算前一步的收益 CE(k=1) − CE(k=2) 和更早历史的收益 CE(k=2) − CE(k=4)。
- n-gram 的学习曲线脚本已有（`prediction/ch5_learning_curve.py`），但现有结果是旧数据集（`taxi_traj20`、`geolife_bj500m`、`highd_v20`）上的，要在新导出上重跑；神经网络补同样的曲线。
- 待定：数据量不同时训练预算怎样定（固定轮数加早停，还是固定梯度步数）。
- 判据（待定稿）：更早历史的收益随数据量增大且没有饱和 → 现有结论部分受数据量限制，可以粗略外推还需要多少数据；早已饱和 → 不是数据量的问题。

## 假设三：个体特征和去抖动能否缩短所需的输入

- 个体特征：车辆或用户的嵌入，只用训练期的数据学。这要求按个体的时间切分：同一个体较早的数据训练、较晚的数据测试。现有导出是每段行程或轨迹内部按时间切分，一个人后面行程的训练部分晚于前面行程的测试部分，用来学个体嵌入会用到“未来”的数据，所以要重新导出；按车辆切分的设置下个体特征用不了。
- 去抖动：去掉 A→B→A 式的来回跳动（做法同 `prediction/taxi_network_controls.py`），只用于输入和训练数据。
- 比较：加或不加，k = 1、2、4、8。
- 判据（待定稿）：加个体特征或去抖动以后，达到同样精度所需的 k 是否变小。合并 n-gram 中加入个体模型只降低 0.02–0.04 bits，收益可能不大，如实报告。
