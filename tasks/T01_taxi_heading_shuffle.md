# T01 出租车留出增益的打乱方向对照

- 执行：Codex　审查：Claude Code
- 状态：待做
- 关联：`STATUS.md` 第 3 节第 2 条、第 7 节第 1 条；`EXPERIMENT_LOG.md`“当前的下一步”中的“出租车留出增益的打乱方向对照”

## 为什么做

中期报告和论文写的是：在出租车 200 m 全局网格的合并估计中，补入设备记录的行驶方向和格内位置后，前一格子的留出增益从 0.403 降到 0.068 bits/步，只剩 17%（`controls/results/heading_state_taxi_200m_device.csv` 第一行：`G2_tuned` = 0.4025，`R_heading+side_tuned` = 0.0683）。另一方面，超额 CMI 只以方向为条件时剩 45%，而把方向在格子内打乱（分层数相同、不含方向信息）也会降到 69%，说明一部分下降只靠把状态切细就能出现。留出增益还没有做这个对照，所以 17% 可能高估了方向的作用。

结果决定“其中相当一部分是状态里缺少的运动量”这句话在出租车上能不能保留、该怎么写。

## 问题

把每次进入格子时的（方向，格内位置）标签在同一格子内打乱以后，前一格子的留出增益还剩多少？和真标签的 17% 差多少？

## 方法

在 `controls/heading_state.py` 里新增一个模式，旧模式的代码路径和输出都不变：

```
python controls/heading_state.py taxi_device_shuffle 0.002   ->  controls/results/heading_state_taxi_200m_device_shuffle.csv
```

1. 数据、切分和划分与 `run_taxi_device` 完全相同：`taxi_fixes_device()` 的定位点（有缓存就用缓存），间隔 > 300 s 处切开，`runs_device` 得到每次进入的格子、方向、格内位置，`crc32(文件名) % 5 == 0` 的车作测试，`inner_split` 取每段训练序列的最后 20% 调 β。只做“设备方向、全部进入”这一种情况（即 17% 那一行）。
2. 打乱的单位是一次进入（`runs_device` 返回的一个元素）。在构建三元组表之前，把全部车辆、训练和测试的所有进入放在一起，按当前格子分层，把（方向，格内位置）成对地随机置换（例如对编码 `h * 9 + side` 用 `geolife_robust.strat_shuffle`，再拆回各段）。这样在全部进入中，每个格子里方向、格内位置及其组合的次数都不变（进入三元组表的行和各个划分里只是近似不变），只去掉标签和轨迹之间的联系。速度不打乱。
3. 置换后按原流程算 `heldout_tuned`（逐层调 β，网格 0.1–100）。报告 `heading` 和 `heading+side` 两组的 GA、R；`heading+side+speed` 一组含没打乱的速度，不报告。`G2_tuned` 与标签无关，应等于 0.4025，用来检查流程没变。
4. 先跑一次不打乱的检查（置换取恒等，单元名 `identity`）：必须复现真标签的结果，heading 的 GA = 0.3298、R = 0.1285，heading+side 的 GA = 0.3311、R = 0.0683。这一步检查标签这条路径没有改错（`G2_tuned` 只用格子，查不出标签的问题）。然后重复 5 次打乱，第 r 次的种子为 `zlib.crc32(f'taxi-device-shuffle|{g}|{r}'.encode())`，r = 0…4。
5. 切分程度的诊断：对真标签和每次打乱，记录训练中不同的（S，A，S−）上下文个数，以及测试步中（S，A）、（S，A，S−）上下文在训练里没出现过的比例。真方向和上一格子关系很强，打乱后的标签和上一格子无关，所以打乱会把（S，A，S−）切得比真标签细得多；这组数字说明对照偏严多少。
6. 每次重复（包括 `identity`）是一个单元，结果原子写入 `controls/work/heading_state/taxi_device_0.002_shuffle/<单元>.json`（先写 `.tmp` 再改名），已完成的跳过；中断后直接重新运行即可续跑。
7. CSV 每行一个单元（含第 5 步的诊断数），另加 `heading`、`heading+side` 两组的均值、最小值、最大值；文件里记录参数（网格、置换方式、种子规则）和运行环境。

耗时参考：原来的 `taxi_device` 三种情况（各含调参留出和 CMI）在云端两核上共用约 12 分钟；本机没有定位点缓存时，第一次还要解析 4,316 个文件。先跑 `identity` 估计时间，再跑其余。

## 判据（跑之前定）

记真标签的 R_真 = 0.0683（heading+side），G2 = 0.4025；R_乱 为 5 次重复的均值。`identity` 没有复现真标签的数字时，先查代码，不往下判。

这个对照偏严：打乱后的标签把（S，A，S−）切得更细（见第 5 步），G2 − R_乱 可以看作真标签下切分效应的上限，所以 (R_乱 − R_真) / G2 是方向本身作用的下限。据此：

- R_乱 / G2 ≥ 0.8：即使按最严的切分，下降也基本来自方向信息。保留“只剩 17%”，补一句“把方向在格子内打乱的对照仍剩 x%”。
- 0.4 ≤ R_乱 / G2 < 0.8：两者都报，写成“方向本身至少解释了前一格子增益的 (R_乱 − R_真) / G2”。
- R_乱 / G2 < 0.4：计数模型在这里分不开方向信息和切分效应。出租车暂不写“相当一部分是缺少的运动量”，等 T03 中 1b 的网络比较（固定容量的网络不会因为多一个没有信息的标签而变好）再定。
- 5 次的极差超过 R_乱 的 10% 时，再加 5 次（r = 5…9）后再判。
- 若第 5 步的诊断显示打乱后未见上下文的比例并不比真标签高，上面“偏严”的前提不成立，在记录里写明，由用户决定怎么写。

`heading` 一组同样报告，与真标签的 R（0.1285，即 31.9%）对照，只作参考。

## 审查要点

- 置换是否按进入、在当前格子内进行，方向和格内位置是否成对置换；全部进入中每个格子里标签的计数是否不变（自己抽查几个格子）；测试部分是否也置换了；
- `identity` 单元是否复现 GA 0.3298 / 0.3311、R 0.1285 / 0.0683；
- 调 β 的流程与真标签时是否完全相同（同一内层划分、同一网格），`G2_tuned` 是否等于 0.4025；
- 第 5 步的诊断是否按真标签和打乱分别算，结论是否用了“偏严”的前提；
- 旧模式的输出是否没变；
- 实验记录和 `STATUS.md` 里的数字是否与 CSV 一致；结论是否按上面事先写好的判据。
