# T03d 假设一 · highD：当前运动状态能否代替更长的历史

- 执行：Codex　审查：Claude Code
- 状态：待做（T03b 通过后开始）
- 关联：`tasks/T03_prediction_design.md` 假设一；`STATUS.md` 第 3 节第 2 条（highD：补全加速度后第三步只增加 0.003–0.006 bits）

## 为什么做

第一部分发现，highD 上补全加速度等运动状态后，历史的作用基本消失。如果在标准的轨迹预测上，短窗口加当前运动状态能达到标准 3 s 窗口的精度，就给出“先给足当前运动状态、再决定看多长历史”的直接依据，而且模型更小、更快，适合实时和嵌入式场景。

## 问题

在 PiP 的 highD 流程上，W ≤ 1 s 的历史加当前运动状态（以及邻车状态），能否在 1–5 s 的 RMSE 上与 W = 3 s 相当？

## 方法

1. 数据、划分、指标与 T03b 相同；测试样本相同（全部设置在同一批测试样本上评估，只截取不同长度的历史）。
2. 输入组合（自车坐标系，与 PiP 相同）：
   - A：只有自车位置序列，W = 0.4、1、2、3 s；
   - B：自车位置序列 + 当前运动状态（纵向、横向速度和加速度，用窗口内的位置向后差分得到，计算窗口计入 W），W = 0.4、1 s；
   - C：B + 邻车状态（前车、左右车道前后车的相对位置、相对速度；没有的车用掩码），W = 0.4、1、3 s。
   共 9 个设置 × 3 个种子 = 27 次训练。
3. 模型：V-LSTM 编码器—解码器（与 T03b 相同结构）；各设置参数量相差 ≤ 5%（T03a `params.py`）。CS-LSTM 在 W = 3 s 的结果直接引用 T03b，作为参照点，不参与比较。
4. 报告：1–5 s RMSE、ADE、FDE；车道保持和换道两类分开；参数量、GPU 和 CPU 推理时间。
5. 主分析用自己差分得到的速度、加速度；highD 自带的速度、加速度（可能用了对称窗口）只作对照，单独一行，不参与判据。

## 判据（跑之前写好）

“相当”按 T03 共同规则（均值差小于种子极差，且各时刻 RMSE 相对差 < 5%）。

- 支持：B 或 C 在 W ≤ 1 s 时，1–5 s 各时刻都与 A（W = 3 s）相当或更好 → 假设一在 highD 上成立；再看 C（W = 1 s）是否与 C（W = 3 s）相当。
- 部分支持：1–3 s 相当、4–5 s 明显更差 → 写成“短时预测中当前状态可代替历史，长时预测仍需要更长历史”，并报告差在车道保持还是换道样本。
- 否定：B、C 在 1 s 起就明显差于 A（W = 3 s）→ 如实报告差多少。
- 功效：若 3 个种子的极差超过 A、B 均值差的一半，加到 5 个种子再判。
