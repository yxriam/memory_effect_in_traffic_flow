# T03e 假设一 · GeoLife：出行层面的上下文能否代替更长的历史

- 执行：Codex　审查：Claude Code
- 状态：待做（T03c 通过后开始）
- 关联：`tasks/T03_prediction_design.md` 假设一；`STATUS.md` 第 3 节（依赖集中在出行层面的变量上）

## 为什么做

第一部分发现，历史的作用集中在少数变量上。在出行层面，这些变量是时间、活动时长、用户等上下文。Hong 等的模型默认看过去 7 天并加入上下文，但没有回答“有了上下文，还需要看多少天”。如果 1–2 天加上下文与 7–14 天相当，输入可以短得多。

## 问题

在 Hong 等的流程上，短历史（1、3 天）加上下文，能否与长历史（7、14 天）在 Acc@1 和 MRR 上相当？

## 方法

1. 数据、划分、指标与 T03c 相同；全部设置在同一批测试样本上评估（以 14 天设置能构造的样本为准，其余设置在同一批样本上截短历史）。
2. 设置（外部仓库配置开关）：
   - 历史：`previous_day` = 1、3、7、14；
   - 上下文：U0 无（`if_embed_user/time/duration` 全关）；U1 时间＋时长；U2 时间＋时长＋用户（论文默认）。
   共 12 个设置 × 3 个种子 = 36 次训练。
3. 模型：论文的 Transformer；各设置参数量相差 ≤ 5%（嵌入拼接改变维度时调 `dim_feedforward` 对齐，写明各设置参数量）。
4. 报告：Acc@1/5/10、F1、MRR、NDCG@10；每个设置的平均输入长度（停留点个数）、参数量、推理时间；**按用户的结果另存**（T03f、T03g 要用）。
5. 先读外部代码确认 `previous_day` 的含义（是否包含当天），写进记录。

## 判据（跑之前写好）

“相当”按 T03 共同规则（Acc@1 差 < 1 个百分点且 MRR 差 < 0.01，并小于种子极差）。

- 支持：U1 或 U2 在 1 或 3 天时，与 U0 或 U2 在 7、14 天中较好者相当 → 假设一在 GeoLife 上成立；同时报告平均输入长度缩短了多少。
- 部分支持：3 天相当、1 天不相当 → 写成“需要的历史从 7 天缩短到 3 天”。
- 否定：短历史在任何上下文下都明显差于长历史 → 如实报告，并按用户看差距集中在哪些人（交给 T03f）。
- 若 U0 本身随历史加长毫无提升，说明这批数据上历史本来就用不上，在记录里写明，判据改按“上下文的作用”解释，由用户确认写法。
