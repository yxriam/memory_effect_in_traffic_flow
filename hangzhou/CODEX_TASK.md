## 1. 要回答的问题

论文目前的主线：在秒到分钟尺度的个体轨迹上，现有数据量下可检出、可利用的依赖集中在最近几步，以前一步为主，其中相当一部分是状态里缺少的运动量（如行驶方向）；航空行程有真实的长程记忆，但集中在行程起点这一个变量上，以“起点＋当前机场”为上下文就能达到看 4 站历史的效果。统一起来就是：历史的作用集中在少数几个变量上，把它们显式作为输入，比加长历史更省数据。

杭州数据要回答四个问题：

- **Q1 数据**：能不能从刷卡记录建出可靠的个人乘车序列？
- **Q2 状态**：记录里只有车号，能不能得到有意义的离散状态（线路）？
- **Q3 记忆**：已知当前乘坐的车辆或线路以后，前一次乘车还带来多少信息？把当前时刻就能得到的信息（乘车时段、工作日或周末、卡类型、个人身份）和当天第一次乘车（行程层面的信息，与航空的起点同类）放进当前状态后，这部分还剩多少？
- **Q4 预测**：在同一批测试步上，显式输入关键变量的模型（当前车辆或线路，加上时段、日类型或当天第一次乘车）能不能达到 2–4 阶链的预测效果？

无论 Q3、Q4 的结果支持还是不支持主线，都如实写。

## 3. 方法

两个时间窗口：

- **分析窗口 W_ana**：2025-02-17（周一）至 03-30（周日），共 6 周，避开春节假期和大部分寒假。
- **校准窗口 W_cal**：2025-01-02 至 01-26。只用来推断线路（阶段 B），与 W_ana 不重叠，以免用同一批转移既定义状态、又测量依赖。

如果阶段 A 发现 W_ana 的数据不够而 1 月够，就把两个窗口对调，并在记录里写明。

### 阶段 A：整理与清点（`hangzhou/build_taps.py`、`hangzhou/inventory.py`）

**A1 解析。**

- 按表号、页号的数值顺序，读 `HANGZHOU_RAW` 下的 `table*/page_*.csv`（utf-8-sig，无表头）和 `table0/page_*.json`。
- 逐行检查格式。不合格的行按文件计数，写进 `results/build_summary.json`，不要悄悄丢掉。
- 卡号无损编码（例如拆成两个 uint64），全部读完后按十六进制顺序统一编号为 int32。编号表只放在 `work/`。
- 车号转成 int32，时间存成整数秒。
- 服务日以凌晨 4 点为界：4 点前的刷卡算前一天（夜班车）。

**A2 去重与重复刷卡。**

- 卡号、时间、车号都相同的记录只保留一条，表内和表间都这样处理。
- 两个表都覆盖的日期上，报告记录重合的比例，用来判断不同批次爬到的内容是否一致。
- 同一张卡在同一辆车上、间隔不超过 10 分钟的连续刷卡，合并为一次乘车（参数 `--merge-sec 600`），并报告合并的比例。
- 输出 `work/boardings_by_day/YYYYMMDD.npz`，按卡号和时间排序。

**A3 日历与完整度。**

- 每个表：记录页号范围和缺失页。页号上限取目录中最大的页号；table6 的上限是 48,701（现有文件数加上 `final_failed_pages.txt` 中的页数）。缺失页指文件不存在，或者不足 200 行而且不是最后一页。缺失页的日期取前后相邻页的众数日期；两边不一致时记为“未定”。
- 每天：记录刷卡数、卡数、车辆数、各小时分布，以及每个表在这一天的现有页数和缺失页数。
- 完整度：
  - 对覆盖第 d 天的每个表 T，令 c_{T,d} = 现有页数 /（现有页数 + 归到这一天的缺失页数）。
  - 这一天的总量估计为 N_d = max_T n_{T,d} / c_{T,d}，n_{T,d} 是表 T 在这一天的记录数。
  - 去重后并集的完整度为 c_d = min(1, U_d / N_d)，U_d 是并集的记录数。
- 可用日要同时满足三条：
  - c_d ≥ 0.95；
  - 刷卡数不低于同类日（工作日或周末）中位数的 0.8 倍；
  - 不在节假日内。
- 输出 `results/inventory_tables.csv`、`results/inventory_days.csv`，以及 `figures/inventory_calendar.png`（每天的刷卡数与完整度）。

**A4 个人序列。**

- 在可用日上，按卡类型分开统计：每张卡的乘车次数、活跃天数、每天乘车次数的分布。
- 定义两类步：
  - **日内步**：s_{t−1}、s_t、s_{t+1} 在同一个服务日内；
  - **连续步**：三者落在连续的可用日内，跨夜也算；遇到不可用日，序列就断开。
- 检查卡号是否持续：在 W_ana 第一周活跃的卡中，最后一周再次出现的比例。

**关口 A**（结果写进 `results/gate_a.json`）：

前三条任一条不满足就停：

1. W_ana 内可用日 ≥ 28 天；
2. 至少有 20,000 张卡，每张卡至少有 20 个连续步；
3. 卡号持续比例 ≥ 30%。

第 4 条不满足时不停，但主分析改为每天只用完整度最高的那个表，并在 DECISION.md 中说明：

4. 在共同日期上，不同批次的记录重合比例 ≥ 90%（重合数除以两表中较少的记录数）。

### 阶段 B：状态（`hangzhou/route_clusters.py`）

后面的每项分析都对三种状态分别做：

- **S_veh**：车号本身。
- **S_pre**：车号前缀（去掉末 3 位）。这是“公司或片区”一级的粗粒度状态，含义尚未证实，结论只作参考。
- **S_route**：从数据推断的线路簇，只用 W_cal 的可用日构建。

S_route 的构建：

1. 对每张卡，取每天第一次和最后一次乘车作为锚点，两类锚点分开处理，记录日期、时刻和车号。
2. 同一张卡、同一类锚点，如果日期相差 1–7 天、时刻相差不超过 15 分钟、车号不同，就在两辆车之间加一条边。边权是支持这条边的不同卡数。
3. 去掉边权小于 3 的边。
4. 用 Louvain 划分社区：`networkx.community.louvain_communities(G, weight="weight", resolution=1.0, seed=zlib.crc32(b"hangzhou-route-clusters"))`。不在图里的车各自成一类。
5. 做以下有效性检查，结果写进 `results/route_clusters_summary.json`：
   - 规模：至少 3 辆车的簇有多少个，簇大小的中位数和四分位距是多少（对照第 2 节的线路数和车辆数）；
   - 稳定性：把 W_cal 分成前后两半，各自聚类，在两半都出现的车上算调整兰德指数（ARI）；
   - 前缀纯度：每个簇内属于同一前缀的车所占的比例。同一线路的车通常属于同一家公司，而这项检查不依赖聚类所用的信号；
   - 覆盖率：W_ana 中落在“至少 3 辆车的簇”里的乘车所占的比例。

**关口 B**：

- ARI ≥ 0.6、前缀纯度中位数 ≥ 0.9、覆盖率 ≥ 0.85 三条同时满足，S_route 才算有效。
- 不满足时就不用 S_route，后面只做 S_veh 和 S_pre，并在 DECISION.md 写明“没有线路层面的状态”。
- 如果用户提供了车号与线路的对照表（见第 7 节），就用它代替推断的线路簇，并报告推断结果与对照表之间的 ARI。

### 阶段 C：记忆的测量（`hangzhou/bus_memory.py`）

**序列与变量。** 在 W_ana 的可用日上，把每张卡的乘车按时间排成序列 s_0, s_1, …，并记录：

- s_0^day：当天第一次乘车；
- τ_t：当前这次乘车的时段，分 5 档：7 点前、7–9 点、9–16 点、16–19 点、19 点以后；
- δ：日类型，工作日或周末；
- κ：卡类型；
- c：卡号。

**复用代码。**

- 用 import 复用 `airports/airport_memory.py` 里的 `cmi_with_null`、`cond_entropy`、`key`，不要复制。
- `key()` 按 (V+1) 的幂给组合状态编码。列数多或状态数大时会溢出 int64，以卡号为条件时一定会溢出。为此写一个安全版本：每组合两列，就用 `np.unique(..., return_inverse=True)` 重新编号。
- 安全版本先在 S_pre 上和原函数对一次，结果应逐位相同。

**合并估计。** 对每种状态，把所有卡的序列放在一起估计。零模型做 20 次分层置换，单位是 bits/步。日内步和连续步分别报告。

1. H(s_{t+1} | s_t)。
2. I2 = I(s_{t+1}; s_{t−1} | s_t)，同时报告返程率 P(s_{t+1} = s_{t−1}) 和一阶链给出的返程率（算法同 `airport_memory.py`）。
3. I3 = I(s_{t+1}; s_{t−2} | s_{t−1}, s_t)。
4. I(s_{t+1}; s_0^day | s_{t−1}, s_t)：当天第一次乘车在最近两次之外还带来多少信息。只用 t ≥ 2 的日内步，因为 t = 1 时 s_0^day 就是前一次乘车。
5. **状态补全**：比较 I(s_{t+1}; s_{t−1} | s_t) 和 I(s_{t+1}; s_{t−1} | s_t, X)，两者用同一批步计算。
   - X 取 τ_t、δ、(τ_t, δ)、κ、c 时，日内步和连续步上都算。
   - X 取 s_0^day 和 (τ_t, s_0^day) 时，只用 t ≥ 2 的日内步，补全前的基准也在这批步上重算。
   - 报告超额和剩余比例（补全后的超额除以补全前的超额），同时报告 X 本身带来的信息 I(s_{t+1}; X | s_t)。
   - X = c 时每层的样本很少，代入值的偏差很大，只解读超额。
   - τ_t、δ、κ、c 都是当前时刻就能得到的量；s_0^day 属于行程层面的信息，与航空的起点同类，要分开写。
   - 不要把“距上一次乘车的时间”放进状态。它是从历史算出来的，加进去以后依赖下降只是换了一种写法，不能作为证据。

**按卡估计。**

- 从 W_ana 中至少有 100 个连续步的卡里，按 crc32(卡号) 固定抽 2,000 张；不足 2,000 张就全取。
- 每张卡做 20 次置换，计算 I2 的超额。报告中位数、四分位距，以及 p < 0.05 的比例。
- 合并估计和按卡的中位数分开报告。**不要**拿一个数据集的合并估计去比另一个数据集按个体算的中位数，两者口径不同。

**稳健性**（只做两项）：

- 把 W_ana 分成前后两半（2 月 17 日至 3 月 9 日，3 月 10 日至 3 月 30 日），各算一遍；
- 再随机去掉 5% 的乘车记录（种子 `zlib.crc32(b"drop5")`），重算合并估计的 I2 超额，看缺页对结果的影响有多大。

按卡类型分开，再报告一次合并估计的第 1、2、5 项。

**输出：**

- `results/bus_memory.csv`：每种状态、每个量一行，含步数、代入值、零模型均值和标准差、超额、p；
- `results/bus_memory_cache.json`：记录参数和运行环境，按（状态，量）缓存结果，用于续跑。

### 阶段 D：留出预测（`hangzhou/bus_heldout.py`）

在连续步序列上预测 s_{t+1}，历史最多看 4 次乘车。序列开头历史不足的部分用起始符补齐。

**两种划分：**

- **D1 按卡**：crc32(卡号十六进制) % 10，0–6 训练，7 验证，8–9 测试。
- **D2 按时间**：W_ana 可用日的前 70% 训练，接下来 10% 验证，最后 20% 测试。同一张卡可以同时出现在训练和测试里，对应“预测某个人下一次乘车”的场景。

**模型：**

- 1–4 阶插值回退链：复用 `airport_memory.py` 的 `Backoff`、`tune`、`ce`。每阶的 β 在验证部分上从 0.1–300 的网格中选。
- 显式输入关键变量的模型：(s_t, τ_t)、(s_t, τ_t, δ)、(s_t, s_0^day)、(s_t, τ_t, s_0^day)，都回退到普通一阶，做法与 `airport_memory.py` 中“起点＋当前机场”的模型相同。s_0^day 是历史变量，含它的模型不要叫一阶模型；比较时报告 4 次乘车的窗口中有多大比例本身已包含 s_0^day（航空数据中这一比例约为 91%，优势来自上下文更紧凑，而不是看得更远）。
- 只在 D2 中做：个人一阶模型（按卡计数，回退到合并的一阶），以及个人加时段的模型。

**评价：**

- 在同一批测试步上比较交叉熵（bits/步），分两个子集：前面至少有 1 次乘车的步，以及至少有 4 次乘车的步。另报 top-1、top-5 准确率。
- 关键差值（例如“最好的显式输入模型减 4 阶链”）按测试卡做 200 次自助抽样（种子固定），给出 95% 区间。区间包含 0 记为“相当”，整个区间都小于 0 记为“更好”。

**输出：** `results/bus_heldout.csv`、`results/bus_heldout_cache.json`。

**DECISION.md**（中文，不超过一页），按以下结构写：

1. **结论**：能用、有条件能用，还是不能用，并给一句理由。
2. **主要数字**（表格）：S_route（或能用的最好状态）的 H(s_{t+1}|s_t)、I2 超额、返程率、补全后的剩余比例，以及同一批测试步上的交叉熵。
3. **与主线的关系**：是支持、部分支持还是不支持“历史的作用集中在少数几个变量上，把它们显式作为输入，比加长历史更省数据”，依据是哪几个数。
4. **限制**：只有上车刷卡，没有站点和下车；线路靠推断；卡类型的构成；爬取时的缺页；一张卡可能有几个人用。
5. **建议**：
   - 要不要写进中期报告或论文。如果写，写在哪里，最多一段话加一张图，并附一段可以直接使用的中文；
   - 能不能作为下一阶段预测研究的数据。

**实验记录。** 按 `experiment_log/TEMPLATE.md` 新建 `experiment_log/<日期>_hangzhou_bus_feasibility.md`，在 `EXPERIMENT_LOG.md` 的总表里加一行，并更新“当前的下一步”。这次是新增分析，不涉及 `tools/check_paper_numbers.py` 中已有的数字，确认后在记录里写明。

## 5. 运行、中断与续跑

在仓库根目录依次运行：

```
python hangzhou/build_taps.py
python hangzhou/inventory.py
python hangzhou/route_clusters.py
python hangzhou/bus_memory.py --pilot     # 只用 W_ana 第一周，记录耗时和峰值内存
python hangzhou/bus_memory.py
python hangzhou/bus_heldout.py
python hangzhou/fig_hangzhou_memory.py
```

- **中断与续跑：** 每个脚本都可以用 Ctrl+C 中断，重新运行同一条命令就从断点继续。`build_taps.py` 按文件记录进度；后面的脚本按（状态，量）或（划分，模型）缓存结果；缓存都先写 `.tmp` 再改名。
- **耗时：** 试跑后估计全量所需的时间。超过 2 小时就把置换次数降到 10，并在记录中写明。
- **内存：** 卡号编号和车号都存成 int32，时间存成整数。不要把几千万行一次读进 pandas 的 object 列。
- **多进程：** 可以用，但写出结果前要先排序，结果不能依赖进程完成的先后。
