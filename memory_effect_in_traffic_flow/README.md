## 📖 Overview

Most traffic and mobility models are first-order Markov: the next state is assumed to depend on the current state only.
This repository asks a simple question across four very different mobility datasets — **does the past beyond the present state carry information, how much, and is that information actually usable for prediction?**

We answer it with a consistent toolbox:

| Tool | What it measures | Where it is used |
|---|---|---|
| Markov-order comparison (held-out log-likelihood / perplexity / BIC) | predictive gain of a 2nd- or 3rd-order chain over a 1st-order chain | highD, taxi, GeoLife (optional), airports |
| Conditional mutual information `I(S_{t+1}; S_{t-1} \| S_t)` with a stratified permutation null | information-theoretic *ceiling* of second-order memory | taxi |
| Entropy reduction `H(next \| current) − H(next \| prev, current)` | memory hidden by a first-order flow representation | GeoLife |
| Velocity autocorrelation + generalised-Langevin memory kernel | shape and power-law decay of long memory in speed | highD, GeoLife (per transport mode) |
| Sankey return-flow analysis, RNN vs LSTM | qualitative "return-to-origin" memory in O-D paths | airports (BTS DB1B) |

The repository is organised as **one self-contained folder per dataset**. Every folder either runs end-to-end from cached results in seconds, or recomputes everything from raw data with a single flag.

## ✨ Highlights

- 🧪 **Four datasets, one question** — highway vehicles (highD), Shanghai taxis (SUVnet GPS), 182 GeoLife users, and 511 k BTS airline O-D paths.
- 📓 **Notebook-first, cache-first** — the highD and taxi analyses are single notebooks where each step states *why*, *what is expected* and *how to read the result*; `RUN_COMPUTE = False` reproduces every table and figure from shipped CSV/NPZ caches in seconds.
- 🎨 **Publication-ready figures** — Nature-palette multi-panel figures (`.png` at 600 dpi + `.pdf`) regenerated by the notebooks.
- 🔍 **Honest estimator analysis** — we show that the *sign* of the second-order gain on taxi data depends on the smoothing estimator (add-α vs back-off β) and tune β on an inner validation split; the information-theoretic ceiling (CMI) is reported next to the realised gain.
- 🧹 **No hidden paths, no secrets** — all machine-specific paths from the research code base were removed; raw data lives in git-ignored `data/` folders with download instructions.

## 📊 Key results

<details open>
<summary><b>highD — highway vehicle speed (60 recordings, 0.2 s steps, 20 speed states)</b></summary>

| Order k | held-out LL / step (nat) | perplexity | gain vs k−1 |
|---|---|---|---|
| 0 | −2.995 | 19.99 | – |
| 1 | −0.397 | 1.487 | – |
| 2 | **−0.293** | **1.341** | +0.103 nat = **26 %** of `H(S_{t+1}\|S_t)` |
| 3 | −0.264 | 1.302 | +0.029 nat |

LRT 2 vs 1: G = 1.08 × 10⁶ on 7.7 M steps, p ≈ 0. The VACF is non-exponential and the discrete GLE kernel has `K[1]/K[0] = −0.65`; the earlier "29 % memory fraction" is **not** reported because it changes sign with the integration window.

<p align="center"><img src="highD/memory_analysis_output_8.0/fig_highD_memory.png" width="85%"></p>
</details>

<details open>
<summary><b>Shanghai taxi — GPS cells (4 307 trajectories, 10×10 / 20×20 / 30×30 grids)</b></summary>

| grid | CMI₂ median (nat) | trajectories with CMI₂ > null | ΔLL(2 vs 1), add-α | ΔLL(2 vs 1), tuned back-off β* | share of 2nd-order wins |
|---|---|---|---|---|---|
| 10×10 | 0.021 | 29 % | −0.169 | −0.003 (mean +0.015) | 48 % |
| 20×20 | 0.027 | 55 % | −0.076 | **+0.008** (mean +0.028, p = 2e-48) | 57 % |
| 30×30 | 0.024 | 66 % | −0.042 | **+0.012** (mean +0.026, p = 8e-122) | 71 % |

Second-order memory is real (CMI significant, robust to a global instead of per-trajectory grid), but it is only ≈ 2–4 % of the residual uncertainty `H(S_{t+1}|S_t)`; a naive second-order chain *loses* to first order unless the smoothing strength is tuned, and even then recovers only 30–60 % of the CMI ceiling. Third-order memory is detectable but never improves prediction.

<p align="center"><img src="taxi/figs/fig_taxi_memory.png" width="85%"></p>
</details>

<details open>
<summary><b>GeoLife — 181 users, 0.0001° grid, per-mode velocity memory at 5 s</b></summary>

- Median entropy reduction `H1 − H2` = **0.346 bits (74 %)**; 180 / 181 users positive; pooled flow 1.74 → 0.68 bits.
- The paper's earlier held-out experiment reported ≈ 12 % higher top-1 accuracy for a 2nd-order chain on the coarse grids; the cleaned pipeline keeps prediction as an *optional diagnostic* (`90_optional_markov_holdout_eval.py`) and the headline result does not depend on it.
- Long memory differs by transport mode (Hurst *H*, ACF power-law α, kernel power-law α at Δt = 5 s): bus `H = 0.87`, bike `0.91`, walk `0.89`, car `0.96`, subway `0.96`, train `0.98`.

<p align="center"><img src="geolife/outputs_clean/figures/fig_geolife_memory_flow_entropy.png" width="85%"></p>
</details>

<details>
<summary><b>Airports — BTS DB1B O-D survey, 2024 Q1 (511 407 paths, 436 airports)</b></summary>

With a first-order chain or an RNN, the airport visited after a hub (e.g. DEN) is independent of where the traveller came from; a second-order chain or an LSTM reproduces the dominant **return-to-origin** flow (3-step return rate 0.97 vs 0.00 for the RNN on a 1000-step rollout). Code in [`airports/`](airports/) is the original research code, kept as a legacy module.
</details>

## 🚀 Quick start

```bash
git clone https://github.com/yxriam/memory_effect_in_traffic_flow.git
cd memory_effect_in_traffic_flow
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                          # numpy / pandas / scipy / matplotlib / tqdm / jupyter
jupyter lab
```

Then open either notebook and **Run All**:

| Notebook | Default (`RUN_COMPUTE = False`) | Full recompute (`RUN_COMPUTE = True`) |
|---|---|---|
| `highD/highd_memory_analysis.ipynb` | reads `memory_analysis_output_8.0/` → all tables + Fig. 1 in seconds | needs `highD/data/*_tracks.csv`; ≈ 10 min single process |
| `taxi/taxi_memory_analysis.ipynb` | reads the six `memory_*.csv` caches → all tables + Figs. 2–3 in seconds | needs `taxi/data/Taxi_070220/`; ≈ 11 min (CMI permutations) + 4 min (β sweep) per grid mode with 2 workers; set `CFG['workers']` and `CFG['grid_mode']` |

GeoLife is a script pipeline (PowerShell wrapper or plain `python`):

```bash
cd geolife
pip install -r ../requirements-full.txt      # adds scikit-learn (and torch for the optional scripts)
python 00_check_environment.py               # checks data_raw/Data/ is present
python 01_preprocess_no_leakage.py
python 02_memory_flow_metrics.py
python 03_memory_driver_correlation.py
python 04a_resample_sensitivity_select.py --sensitivity-max-files-per-mode 100000 --gap-sample-files-per-mode 100000 --max-gaps-per-mode 10000000
python 05_summarize_results.py               # -> outputs_clean/summary_report.txt
```

Shipped `geolife/outputs_clean/` already contains every CSV and figure produced by that pipeline, so the tables in the paper can be inspected without the raw data.

| Paper item | Produced by |

| Fig. 2 / Fig. 3 taxi | same notebook → `taxi/figs/` |

| Airport Sankey diagrams, RNN vs LSTM return rates | `airports/lstm_markov/lstm_rnn_predict.ipynb`, `airports/markov_chain/airports_sankey*.py` |

Two implementation details worth knowing before you change the taxi code:

1. **All Markov orders must share the same smoothing.** Mixing an add-α first-order model with back-off higher orders mis-attributes ≈ 0.6 nat/step of "first-order prior spread" (30×30 grid) to higher-order memory.
2. **β must not be chosen on the test segment.** The notebook splits the training segment 75/25, picks β* per order on the inner validation split (pooled over trajectories) and only then scores the test segment.
